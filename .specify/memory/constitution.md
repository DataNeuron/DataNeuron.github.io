# DataNeuron Portfolio Site Constitution

## Core Principles

### I. Clean Code

- All content files (Markdown, HTML, YAML, Liquid templates)
  MUST use consistent indentation (2 spaces for YAML/HTML,
  standard Markdown formatting for `.md` files).
- File and directory names MUST be lowercase, hyphen-separated,
  and descriptive (e.g., `my-new-post.md`, not `post1.md`).
- Markdown files MUST NOT contain trailing whitespace or
  consecutive blank lines exceeding one.
- Front matter in posts and pages MUST include all required
  fields (`layout`, `title`, `date` for posts) and MUST NOT
  include unused or empty keys.
- Liquid template logic MUST be minimal and readable; complex
  conditionals MUST be broken into includes where possible.
- Commit messages MUST be concise and describe the content
  change, not implementation details.

### II. Framework Preservation (NON-NEGOTIABLE)

- The Jekyll framework, Minimal Mistakes remote theme, and
  all existing configuration MUST NOT be modified.
- `_config.yml` MUST NOT be altered unless adding new content
  metadata (e.g., a new collection); theme settings, plugin
  lists, and permalink structures are frozen.
- No new Jekyll plugins MUST be added beyond those already
  declared in `_config.yml` and `Gemfile`.
- Theme overrides via `_layouts/`, `_includes/`, or `_sass/`
  MUST NOT be introduced unless the remote theme explicitly
  supports the override and the change is content-driven
  (not framework-driven).
- The `remote_theme` value (`mmistakes/minimal-mistakes`)
  MUST remain unchanged.
- All content MUST work within the existing theme's
  capabilities; features requiring theme modification MUST
  be rejected.

### III. No Testing (NON-NEGOTIABLE)

- This project MUST NOT include any test suites, test
  frameworks, test runners, or test configuration files.
- No CI/CD pipelines for automated testing MUST be created
  or configured for this repository.
- Validation of content is performed manually via
  `bundle exec jekyll serve` and visual inspection only.
- Spec and plan artifacts generated by SpecKit MUST omit
  all test-related tasks, phases, and checkpoints.
- The "Tests" sections in task templates are explicitly
  marked OPTIONAL and MUST be excluded for all features
  in this project.

## Content Standards

- Posts MUST reside in the `_posts/` directory following the
  `YYYY-MM-DD-title.md` naming convention.
- Static pages MUST reside at the repository root or in a
  clearly named directory (e.g., `about/`, `cv/`).
- Images and assets MUST be placed in the `images/` directory
  with descriptive filenames.
- All Markdown content MUST use proper heading hierarchy
  (no skipping levels, single H1 per page).
- Links to external resources MUST use HTTPS where available.

## Development Workflow

- All changes MUST be committed to the `master` branch
  (GitHub Pages source branch).
- Content MUST be previewed locally with
  `bundle exec jekyll serve` before pushing.
- Each commit MUST represent a single logical change
  (one post, one page update, one config addition).
- Binary files (images, PDFs) MUST be optimized for web
  before committing to keep repository size manageable.

## Governance

- This constitution supersedes all other development
  practices for the DataNeuron portfolio site.
- Amendments MUST be documented with a version bump,
  rationale, and updated date.
- Version changes follow semantic versioning:
  - MAJOR: Principle removed or fundamentally redefined.
  - MINOR: New principle or section added.
  - PATCH: Clarifications or wording refinements.
- All content and configuration changes MUST be verified
  against these principles before committing.
- Framework Preservation (Principle II) and No Testing
  (Principle III) are NON-NEGOTIABLE and MUST NOT be
  amended without explicit owner approval and a MAJOR
  version bump.
